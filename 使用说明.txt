DrumQuill（DrumQuill）· 使用说明



====================







【最常用方式：双击 start.bat】（推荐）



1. 双击程序目录下的 start.bat



   → 首次运行会自动检测并安装依赖（Python 环境 + AI 模型，约 500MB，走国内镜像）



   → 装完自动弹出「DrumQuill · 扒鼓谱」窗口（网页版，地址 http://127.0.0.1:8756）



2. 把音乐文件（MP3/WAV/FLAC/M4A）拖进页面，或点击选择



3. 速度 BPM 留空（自动检测）；自动结果若不准，可手动填入（如 156）



4. 点「开始扒谱」，一首 4 分钟的歌约需 15–30 分钟（CPU 模式）



5. 中途可以关掉窗口去忙别的；后台任务不会中断（关窗时会有提示）



6. 页面「已完成的鼓谱」保留全部历史成品，可随时下载







   ★ 想取消当前任务：页面点「取消任务」即可（中间文件不会被删）



   ★ 旧习惯入口：启动扒谱.bat 是兼容别名，和 start.bat 完全等价。







【拖拽方式：一键扒谱.bat】



   把音乐文件直接拖到「一键扒谱.bat」图标上 → 自动检测依赖 → 开始扒谱。



   适合不开网页、命令行跑批。







   成品文件在程序目录下的 output\ 与 midis\ 里。



   · 歌曲名_鼓谱.pdf    —— 打印 / 查看用（专业排版，含速度与拍号）



   · 歌曲名.musicxml    —— MuseScore 打开后可编辑、校对、重新导出



   · 歌曲名_BPM_al.mid  —— 可在任意 DAW / 播放器对照试听



   · 歌曲名_鼓谱音频.mp3 —— 纯鼓声伴奏（无 ffmpeg 时为 .wav）







【自动回退（装不齐也能用）】



   · Demucs 分离失败      → 自动改用整曲直接转录（精度略降）
   · Beat This 拍点不可用 → 退回「全曲一个固定速度」记谱，小节容易和音乐对不上
                            （结果页会明确提示；补装「节拍跟踪模型 Beat This」后重跑即可）



   · 没装 MuseScore 4    → 自动用自带 SVG→PDF 出谱



   · 没装 ffmpeg          → 音频保留 WAV 不出 MP3



   · 自动测 BPM 失败      → 用 120，网页可手动改



   · 端口 8756 被占用     → 自动换 8757



   详见 docs\fallback_matrix.md。







【怎么校准鼓点】（AI 转录的常见弱项）



   镲片（crash/ride）、花式加花（fill）、开闭镲、鬼音最容易漏或错。



   用 MuseScore 4 打开 .musicxml，对照原曲边听边改：



   文件→打开→选 musicxml → 播放对照 → 改错处 → 文件→导出 PDF。







【常见问题】



   · 首次安装很久/卡住：网络慢时约 1–3 小时，可断点续传，关掉重开 start.bat 接着装。



   · 想看配置：复制 config.json.example 为 config.json，可改 venv 位置、端口、数据目录。



   - 需要系统 Python 兜底时，把你的 pythonw.exe 路径写进 config.json 的 venvDir 即可。



     所有 AI 依赖都在独立虚拟环境，互不影响。







【技术栈】



   Demucs v4 htdemucs（分离鼓轨，CPU）/ ADTOF-pytorch（鼓轨→MIDI，5 类鼓）



   MuseScore 4（可选，MusicXML→专业 PDF）/ Flask + pywebview（本地界面）



   ? ADTOF 权重为 CC BY-NC-SA 4.0，仅限个人非商用（见 docs\third_party_licenses.md）。















【分离模型怎么选】



   设置 -> 分离模型：可下载 / 切换 / 删除。



     默认 HTDemucs 最快最稳；HTDemucs-FT 略细；MDX-Extra 镲片最准但慢 3 倍；HTDemucs-6S 属实验项。



     实测四个模型整体差距只有 1% 左右——换模型救不了错谱，镲片乱才值得换。



   显存分档推荐：无显卡或 4-6GB 用默认；6-12GB 用 FT；12GB+ 用 MDX-Extra。



   产物目录：stems\模型名\歌曲名\drums.wav。







【更新后像没生效】



   app.py 启动时写 app\service_stamp.json 指纹；launcher 发现程序文件变了会自动重启服务。



   仍无效则结束 pythonw.exe（命令行含 app.py）再启动。















【想让谱子更准：两个开关】



   设置 -> 常用设置里有两项，默认值已经是实测最优，一般不用动：



     · 转录阈值  底鼓,军鼓,嗵鼓,踩镲,吊镲（留空 = 按当前分离模型自动）



       越小越灵敏（会多打出一些音符），越大越保守。实测调优后底鼓/踩镲更灵敏、嗵鼓更严。



     · 量化吸附容差 0-0.5（默认 0.25，0 = 完全不量化）



       原来的做法是把每个音符硬吸到十六分音符上，实测会让准确度明显下降（演奏本来就不在栅格上）。



       现在只吸偏离 25% 以内的音符，谱面照样整齐。



   实测（同一首歌 150 秒，逐类微平均 F1）：改造前 0.81 -> 现在 0.89（前 60 秒）/ 0.83 -> 0.92（后段）。



   另外：力度不再一律 100，试听能听出强弱。







【已知的上限（不是 bug）】



   ADTOF 只输出 5 类鼓：底鼓、军鼓、嗵鼓、踩镲、吊镲。



   没有叮叮镲(ride)，也不分开/闭踩镲 —— 所以 ride 段落常被记成吊镲或踩镲，这类错误调参数救不了。

【2.1.1 更新要点】
· 首次启动检测到缺依赖：弹窗确认后自动打开安装窗口（多镜像、可断点续传），装完自动继续启动，不再卡「服务启动超时」。
· 练习页有成品时自动接上最近练的一首：刷新、重开软件都不会再出现「还没有谱面可练」的空页面。
· 节拍跟踪模型 Beat This（77MB）下载支持断点续传：没下完或失败时，在「设置 → 组件」里点「补装」接着下，不阻塞扒谱。
· 取消任务立即生效：不会再出现「点了取消，任务又被队列拉起来接着跑」。
